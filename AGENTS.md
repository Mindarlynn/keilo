# Repository Instructions

## Planning

When turning a user request or high-level concept into an implementation plan:

1. Read `docs/rule/README.md`.
2. Read `docs/rule/workflow.md` and follow its branch, commit, pull request, and exception rules.
3. Read `docs/rule/planning.md`.
4. Read any other rule files relevant to the requested area.
5. Check `docs/plan/active/` for active plans that may affect the work.
6. Use `docs/log/` only when decision history or rationale is needed.
7. Keep the plan minimal and directly tied to the requested goal.
8. Include relevant risks and mitigation before implementation.

## Development

Before making code or behavior changes:

1. Read `docs/rule/README.md`.
2. Read `docs/rule/workflow.md`.
3. Read `docs/rule/development.md`.
4. Read `docs/rule/testing.md`.
5. Read any other rule files relevant to the changed files or feature.
6. Treat `docs/rule/` as the current mandatory policy.
7. If an older plan or log conflicts with a rule, follow the rule.
8. Keep the change minimal and avoid unrequested functionality.
9. Add or update tests that cover the changed behavior.
10. Update related documentation, plans, logs, or rules when the change alters documented behavior or mandatory policy.
